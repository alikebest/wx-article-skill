# 排版：补齐 front matter，按主题调整格式，生成预览

排版**只动格式，不动内容**：不改句子、不增删观点和事实。想改内容是重写或美化的事。

输出 `<名>.layout.md` 和预览页 `<名>.layout.html`。

## 步骤

1. **读输入 md。**
2. **确定 front matter**（规则见下一节）。
3. **调整正文格式**（允许和禁止的改动见后文）。
4. **写入 `<名>.layout.md`。**
5. **运行 `check <名>.layout.md`。** 有错误必须解决；警告能解决的解决，解决不了的告诉用户。
6. **运行 `preview <名>.layout.md --open`**，生成预览页并用浏览器打开。
7. **回复用户**：输出路径、用的主题、改了哪些格式、检查结果里剩下的警告。md 所在文件夹里还没有 `cover.jpg` 时，提醒用户把封面存成 `cover.jpg` 放进去，放好后重新检查。提醒用户先看预览，满意了再说"推送"。

## front matter

| 字段 | 怎么定 |
|---|---|
| `title` | 输入里有就保留。没有就用正文第一个 `#` 标题；也没有就按 titles.md 拟一个，并在回复里告诉用户 |
| `author` | 输入里有就保留；没有就不写，推送时用配置里的默认作者 |
| `digest` | 输入里有且不超过 120 字就保留；没有或超长就写一个 40~120 字的 |
| `cover` | **固定写 `cover: cover.jpg`**，输入里原来是别的值也改成它（改了要在回复里说明）。封面图由用户自己准备，统一命名为 `cover.jpg`，放在 md 所在的文件夹，见 SKILL.md「封面」 |
| `theme` | 用户指定的优先；其次是输入里已有的；都没有就按内容推荐（见下表），并告诉用户可以换 |
| `account` | 输入里有就保留；用户说了这篇发哪个公众号，就写那个账号名（`config` 能看到有哪些账号）；都没有就不写，推送时用默认账号 |
| 其余字段 | 原样带过去 |

| 主题 | 风格 | 适合 |
|---|---|---|
| `lime`（默认） | 荧光柠绿 · 新粗野主义：黑白高对比，柠绿/电紫点缀，粗描边硬阴影 | AI 工具、独立开发、效率工具、科技资讯 |
| `pink` | 樱花粉 · 荧光笔：柔和手账风，粉色荧光笔划重点 | 数码好物、轻松科技话题、生活类内容 |
| `neu` | 新拟态：整篇冷灰底，元素同色，只靠明暗两道阴影做出凸起、凹陷，一个强调蓝 | 数码硬件评测、参数对比。深色模式下浮雕感会消失，推荐时要提醒 |
| `clay` | 黏土拟态：整篇淡紫蓝底，马卡龙色、超大圆角、鼓鼓的三层阴影 | 科普小报、新功能科普、数码入门；不适合严肃的深度分析 |
| `flat` | 扁平化：白底，纯色块、零阴影零渐变、四色撞色 | 日更资讯，深色模式下最稳 |
| `minimal` | 夸张极简：米白底，72px 超大序号、超大数字、大量留白，一个橙红强调色 | 观点、深度解读、年度盘点等"一篇只讲一件大事"的特刊，最好 3~4 节；不适合快讯、参数汇总 |
| `bento` | 便当盒网格：开头自动生成"本期速览"格子盒，小标题、卡片都是圆角格子 | 周报、发布会总结、参数汇总这类信息点多的内容 |

## 各主题怎么渲染各种写法

### 结构规则（所有主题相同）

| Markdown 写法 | 结构规则 |
|---|---|
| 第一个 `##` 之前的 1~3 段文字 | 包成导语卡（中间不能有列表、引用、表格、代码块）；`minimal` 排成灰色副标题 |
| `## 标题` | 可编号的 ≥2 个时自动编号；"附"开头的不编号；标题里手写的"一、""1."会被去掉 |
| `#### 标题` | 最小一级，`#####` 及更深会丢样式 |
| `**加粗**` | 每段最多一处；小标题里的加粗不变色 |
| `*斜体*` | 不显示成斜体，是"重点句"的强调 |
| `> 💡 内容` / `> ⚠️ 内容` | 技巧卡片 / 避坑卡片，开头的符号由卡片小标题代替 |
| `> 内容` | 普通引用，原样引述用 |
| `- 项` / `1. 项` | 转成"符号 + 段落"；项目以 ❌ ✅ 💡 这类符号开头时不再加符号 |
| `![说明](图.png)` | alt 有实际意义时在图下显示图注；"图片""配图"、文件名这类不显示 |
| `---` | 分割线 |
| 表格 | 建议不超过 4 列 |
| 代码块 | 没有语法高亮 |
| `- [x]` 任务列表 | 保留复选框，不可勾选 |

### 新主题多出来的写法

**数据列表**（`neu` `clay` `flat` `minimal` `bento`）：无序列表 1~3 项，每项都是"加粗数值 + 空格 + 简短说明"，会排成该主题的数据组件——`neu` 凸起数据圆盘、`clay` 彩色数据卡、`flat` 纯色数据磁贴、`minimal` 超大数字（1 项 96px，2~3 项并排）、`bento` 一行数据格。`lime`、`pink` 里它就是普通列表。

```markdown
- **35dB** 降噪深度
- **30h** 综合续航
- **¥999起** 售价
```

识别条件：数值含数字且不超过 8 个字、不以"第"开头；说明不超过 14 个字；加粗后面不是冒号；不在引用或嵌套列表里。想保持普通列表，在加粗后面加冒号（`- **30h**：续航`）。

**`minimal` 的引用和转场：**

- 引用去掉出处后不超过 60 字 → 26px 大号金句，里面的 `*关键词*` 变成橙红反白块；更长的排成 17px 引语。
- 引用的最后一段以"——"开头 → 排成极小的出处。
- 单独成段的 1~4 个字、以"。""！""？""……"结尾（如"但是。"）→ 64px 超大关键词转场，标点用橙红。

**`bento` 的本期速览：** 可编号的 `##` 有 2 个以上时，在导语之后自动生成，每节一格、格子里放编号和小标题。小标题太长会在格子里折成好几行。排版时不为此改小标题措辞，有超过 12 个字的就在回复里提醒用户。

## 允许的格式调整

- 删掉与 `title` 相同的正文 `#` 标题（推送时也会自动去重）；其他 `#` 标题降为 `##`。
- 理顺标题层级：章节用 `##`，子项用 `###`，不跳级。去掉 `##` 里手写的编号。
- 让开头成为 1~3 段的导语：原稿开头段落太多时，只把真正的导语留在第一个 `##` 之前，其余放进第一个章节；开头没有文字段落就不加。
- 把原本就是技巧、警告的段落改成 `> 💡` / `> ⚠️` 卡片，全文不超过 3 处；不要把普通段落包成卡片。
- 把原本就是并列项、步骤的连续段落改成列表；两个以上对象在多个维度上对比的内容整理成表格。
- 用支持数据列表的主题时：原文里本来就有 1~3 个并列的关键数字（续航、价格、提升幅度这类），可以整理成数据列表；数值和说明都取自原文，不新增、不换算。`minimal` 的金句、出处、转场同理：只在原文本来就有这样的短句、出处、单独短段时用，不为了效果加句子。
- 列表项开头去掉手写的符号（"·""●""1、"），排版会自动加。
- 给有实际内容的图片补上 alt 作图注（说明来自上下文，不编造）。
- 删掉残留的 HTML 标签（只留里面的文字）、"附：备选标题"附录、无意义的空行和不间断空格。
- 外链图片（http 开头）发出去会显示不出来：问用户是否下载到 md 同目录的 `images/`，同意的话下载后改成相对路径。
- 正文里的链接只有同一主体的公众号文章能点开，其他网址保持纯文字就好，不必改成链接写法。

## 不允许

- 改写、增删句子，调换段落里的句子顺序。
- 增删事实、数字、例子；改标题以外的措辞。
- 写 HTML 标签、脚注、数学公式、引用式链接 `[text][ref]`（都不会被解析，会原样显示）。
