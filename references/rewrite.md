# 重写：把别人的文章用自己的话重新写

适用于别人写的文章。目标是保留全部事实，叙事和语言完全换成自己的。作者自己写的稿子用美化（polish.md），不要用重写：重写会把技巧、例子、口吻当成"非事实"丢掉。

## 流程

| 遍 | 谁来做 | 输入 | 输出 |
|---|---|---|---|
| 第一遍：事实清单 | 主对话 | 原文 md | `<名>.facts.md` |
| 第二遍：成文 | 子代理 | **只有**事实清单 | `<名>.rewrite.md` |
| 第三遍：去 AI 味 | 同一个子代理 | 第二遍的成文 | 原地改写 `<名>.rewrite.md` |
| 核对 | 主对话 | 清单 + 成文 | 必要时修正 |

**为什么第二遍要交给子代理：** 看过原文再写，很容易顺着原文的句子和段落结构走。子代理是全新的上下文，只给它事实清单，写出来的才是自己的叙事。所以主对话不要把原文内容放进子代理的提示里，也要明确告诉子代理不要去读原文。

没有子代理工具（Agent / Task）时，在主对话里依次做第二、三遍，并告诉用户：这种情况下和原文表达的隔离会弱一些。

---

## 第一遍：事实清单（主对话）

通读原文，把所有客观事实逐条列出，供另一位编辑在**不接触原文**的情况下写稿。

1. 一条事实一行，以 `- ` 开头，写清主体（谁、哪个产品）、动作或变化、数字与单位、时间、条件、来源引述（如"某某表示"）。
2. **数字逐字搬运**：百分比、金额、版本号、参数值、日期、倍数一律照抄原文表述，严禁换算或换说法（"三折"就写"三折"，不能写成"3%"；"10% 到 20%"不能改成"最多 20%"）。
3. 专有名词逐字保留：产品名、公司名、人名、功能名、网址，一字不差。
4. 观点与引述注明出处："谁说的、谁披露的"写进对应条目。
5. 只提取原文明确写出的事实，不推断、不补充、不解读，没把握的不写。
6. 图片按 `- 配图：![说明](images/xxx.png)` 单独列出，占位符原样照抄。
7. 原文标注了作者或来源媒体的，单独列一条"作者/来源"。
8. 忽略原文一级标题，以及只含时间戳、标签的元数据行。其他引用块（引述、说明、资料来源、适用范围、免责声明）是正文内容，照常提取。

`<名>.facts.md` 的格式：

```markdown
# 事实清单

来源：<source_url，没有就省略这一行>

- （事实 1）
- （事实 2）
- 配图：![说明](images/xxx.png)
- 作者/来源：（如有）
```

## 第二遍：成文（子代理）

以资深公众号主笔的身份，把事实清单重新讲成一篇高可读性的公众号文章。下文的"素材"就是事实清单。

### 1. 用自己的叙事重新讲

- 清单只是底层素材。严禁顺着条目做同义词替换，严禁照搬清单的排列顺序，用自己的逻辑重新组织。
- 叙事视角：像一位懂行的编辑跟读者聊这件事，讲清"发生了什么、跟读者有什么关系"，用具体的人群和场景代入。设问全文最多 1~2 处，只用作章节之间的过渡，不要用设问开段。
- 先判断文章类型，再按对应骨架重新规划小标题与板块：
  1. 单条快讯解读：发生了什么 → 和以前相比变了什么 → 谁会受影响、能怎么用 → 限制与注意事项。
  2. 实测/横评：测什么、怎么测 → 结果并排对比（配图、数据放在一起看） → 第三方或评审视角 → 结论与各自适用场景。
  3. 资讯合集：开头一两句交代这期有几条、最值得看的是哪条；每条一个独立 `##` 小节，讲清"是什么 + 为什么值得关注"，不强行串联。
  4. 教程/实操：适用场景 → 准备工作 → 分步操作 → 常见坑与注意事项。
  5. 清单/资源汇总：开头说清这份清单解决什么问题、适合谁；按用途分组，每组一个 `##`，组内用列表，每个条目的名称、链接原样保留。
  都不贴切时按事实本身的逻辑组织。骨架只决定内容顺序，小标题仍要用自己提炼的观点来写，不要直接写"发生了什么""测试设定"这类骨架名。
- 可以在事实之间做横向对比、点出对不同人群的影响，但只能基于清单，不推演清单里没有的体验、条件或结论。

### 2. 结构与层级

- `##` 作大章节，`###` 作子步骤或小分类，不跳级。不写一级标题。`##` 小标题不带编号（"一、""1.""01"），排版时会自动编号。
- 第一个 `##` 之前写 1~3 段导语，交代这篇讲什么、适合谁。排版时它会变成导语卡。
- 段落长短交错：关键判断、转折可以单句成段；交代背景的段落可以长一些（手机上不超过 6 行）。
- 正文严禁 `---`、`***`、`___` 分割线，只用空行和小标题区分层次。
- 以一个独立的 `##` 章节收尾，写读者能落地的信息：对谁有用、现在能怎么用或该注意什么、还有哪些限制（2~5 行）。小标题要具体（如"哪些人现在就能用上"），不写"总结""结语"；严禁金句、口号、"未来可期/拭目以待"。

### 3. 视觉锚点（按语义用，不凑数）

- 加粗：只加粗读者扫一眼就该看到的核心结论，每段最多一处，不整句整段加粗。
- 行内代码：只用于读者可能要输入或复制的内容（命令、路径、文件名、参数、模型 ID）。产品名、公司名、文件格式用普通文字。
- 表格：两个以上对象在两个以上维度上对比时用，最多 4 列。
- 列表：并列要素、操作步骤用列表。列表项开头不加 emoji，只有正反对比可以用 ❌ / ✅。
- 提示卡片：`> 💡 ` 关键技巧，`> ⚠️ ` 避坑警告，原样引述原话用不带标记的 `> `。全文不超过 3 处。

### 4. 事实红线

- 改的是叙事和语言，事实绝对不变：因果、数量、定性与清单一致。
- 数字零容忍：清单里的数字逐字搬运；清单里没有的数字、结论、因果，一个都不能出现，宁缺勿错。
- 图片占位符一字不动，放在最契合的段落之间，一张都不能少。
- 命令、代码、路径、参数、版本号、报错信息逐字保留。
- "如""比如"后面是举例，不能改写成上限、下限或唯一选项（"如 8 页 PPT"不能写成"8 页以内的 PPT"）。
- 程度词和比较级如实："能力强"不能写成"最强"，"有助于"不能写成"大幅提升"。
- 不添加清单没有的适用条件、资格限制、产品术语。

### 5. 标题与摘要

按 titles.md 构思 5 个候选标题，选一个作 `title`，再写 `digest`。

## 第三遍：去 AI 味（同一个子代理）

把第二遍的成文当作别人交来的稿子，逐段检查并改写，让语言自然、利落、克制，读起来像资深中文专栏作者的手笔。

1. **欧化翻译腔**：去掉"在……的背景下""随着……的发展""基于……的考量""通过……的方式"这类前置修饰，主语和动词提前；"进行了深入的研究"改成"深入研究了"；削减机械的"它/该/其"；英文式被动句改主动（"被广泛认为是"→"普遍认为"）。
2. **假揭示与伪深刻**：去掉无实质对立的"不是 X 而是 Y""不仅是 X 更是 Y"；去掉"看似 X，本质其实是 Y""这背后折射出""最底层的逻辑是"；删掉段末无信息增量的感悟式升华。
3. **假连接词与推论台阶**：去掉段段都有的"然而、此外、因此、值得一提的是"；删掉"这意味着 → 这说明 → 由此可见"式的空转推论。
4. **黑话与强行展望**：去掉"全方位赋能、深度闭环、打造生态、构筑底座"，直接写谁用了什么、解决了什么；文末不写"未来可期""拭目以待""仍需市场检验"，停在最后一个有实质内容的事实上。
5. **标点与节奏**：破折号解释改用逗号或分句；去掉"原因很简单：""逻辑很直接："这类空壳预告；不硬凑三连排比；长短句错落。
6. **自问与报幕**：去掉"你可能会问""我并不是说……但是""话不多说""让我们一探究竟"。

边界：

- 自然不等于降格口语化：不加网梗、低幼黑话、无厘头语气词，不编造第一人称经历。
- 事实先行，评价克制：不扩大推论，不把相关说成因果，不补充原文没有的论据。
- front matter、图片占位符、数字、代码、链接、标题保持不变；只改正文叙述。

---

## 输出格式

`<名>.rewrite.md`：

```markdown
---
title: （选定的标题）
digest: （40~120 字）
（输入里有的 author / cover / thumb_media_id / theme / source_url / source_author / source_time，原样照抄）
---

（导语 1~3 段）

## （第一个章节）
……
```

- 不写一级标题，不加"附：备选标题"，正文里不出现 `---`。
- 输入里没有的 front matter 字段不要编，尤其不要把原文作者填进 `author`、不要填 `cover`。

## 启动子代理

用 Agent 工具（subagent_type 选 general-purpose），提示按下面填好再发。所有路径用绝对路径。

```
你是公众号主笔。请按下面的要求写一篇文章，全部完成后再回复。

1. 读写作规范：<skill目录>/references/rewrite.md 里的「第二遍：成文」「第三遍：去 AI 味」「输出格式」三节，
   以及 <skill目录>/references/titles.md。
2. 读事实清单：<facts.md 绝对路径>。这是你唯一的素材。
   不要读取 <原文 md 绝对路径> 或同目录下的其他 md，也不要上网搜索原文。
3. 按第二遍写出全文，写入 <rewrite.md 绝对路径>。front matter 除 title、digest 外，原样写入这些字段：
   <逐行列出要带过去的字段，如 cover: cover.png；没有就写"无">
4. 按第三遍逐段检查并改写这个文件。
5. 回复：5 个候选标题（标明类型和选中的那个）、文章类型、全文字数。不要在回复里贴全文。
```

## 子代理完成后（主对话）

1. 读 `<名>.rewrite.md`，核对：
   - 数字、专有名词、链接与事实清单一致，没有清单之外的数字或结论；
   - 清单里的配图全部出现，路径没变；
   - front matter 字段齐全，没有编造的 author / cover；
   - 抽几句和原文对照，没有整句照搬。
2. 发现问题直接修正文件，修了什么在回复里说明。
3. 回复用户：输出文件路径、选中的标题和其余 4 个候选、文章类型。提醒下一步可以排版。
